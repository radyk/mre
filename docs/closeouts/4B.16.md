# Session 4B.16 — the counterfactual and the opener

**2026-07-29** · docs/07 v2.61 (§5a.49–50) · docs/04 session amendment
· no solve ran; the pinned world is untouched

Two questions a planner asks NEXT, neither of which had a route.

4B.14 taught the product to say what is holding an operation where it is. The
question that follows is **"so what would have to be different?"** — and it
would have been swallowed by `swap-move`, which weighs a board move between two
orders and prices it in the sandbox, or by `advice`, which is about the plan.
Both are the adjacent-match failure: an answer to something else, with perfect
citations.

4B.15 taught it to ground a capability claim in docs/05. The question a stranger
opens a board with is **"what should I be looking at?"** — and three of its four
common phrasings were shape reads that parse rule 7 correctly sends to
`unmatched`, where the second tier reasons out an answer the document could have
testified to.

## Item 1 — the counterfactual

`what-would-change` joins the closed vocabulary (parse prompt **v13**;
`src/mre/modules/counterfactual.py`, pure). It computes **no new bounds**: it
takes the docs/05 family that BINDS — which the 4B.14 blocker analysis already
names — and reports the change that would move THAT bound, with its threshold
and the arithmetic.

Rendered on the pinned board, for the specimen the brief set it against:

```
ORD-000013 op20 needs 7h11m in one piece. The last stretch before where it
sits that was too short ran Tuesday 2026-01-13 14:06-19:00 on PAINT-01 —
4h54m, 2h17m short.

To fit Tuesday, one of these has to change:
  op20 declared splittable with a minimum piece of 215 minutes or less
      [docs/05 C3 · docs/06 §5.3 routing_lines.csv splittable / min_chunk_minutes]
      the run phase becomes resumable, so the 4h54m still open is enough to
      START it — R-C3 caps the piece at half the 7h11m it needs (431/2 = 215)
  op10 finishes by 2026-01-13 11:49 instead of 2026-01-13 14:06 (2h17m earlier)
      [docs/05 A1/A2 · docs/06 §5.3 routing_lines.csv sequence]
      that leaves the whole 7h11m before PAINT-01 closes at 19:00
  PAINT-01's Tuesday window extended by 2h17m (past 19:00)
      [docs/05 C1/C2 · docs/06 §5.6 calendars.csv exception rows]
      declared overtime or a longer shift — 4h54m open plus 2h17m is the
      7h11m it needs

If any of these changed, the next bound would be an earlier step
[docs/05 A1/A2] at Tuesday 2026-01-13 14:06 — that removes the barrier; it
does not place the operation there.

Between that window and where it sits, PAINT-01 is closed for planned
maintenance from 2026-01-14 00:00 to 2026-01-14 23:59. Lifting it would
plainly move this, and I haven't priced it: I can't say what the machine's
open hours would be on a day the calendar declares shut.

PAINT-01 is the only machine capable of this operation, so there is no other
lane to move it to.

Can't be priced as a change (it would take a re-solve): B7/B8
sequence-dependent changeover.

Not weighed here (docs/05): B3/B5 …; B7/B8 …; C4 …; F3 ….
```

### The brief's own worked specimen has a wrong number, and the verification found it

The brief proposes `min_chunk_minutes <= 240`. **240 does not work.** R-C3's
degenerate-split rule makes an operation resumable only if its duration is at
least twice the minimum piece, so at 216 the solver treats a 431-minute
operation as atomic again and Tuesday is out of reach. The computed ceiling is
**215 = floor(431/2)**.

That is not a lucky catch. Every lever is verified by **re-running the same scan
under the hypothetical**, and a lever the scan does not confirm is dropped
rather than stated — which is what stops this route from being arithmetic about
arithmetic. The subtlety worth recording: `earliest_fit` does **not** know about
R-C3 (its caller applies it), so verifying with a bare `splittable=True` would
have confirmed 240 happily. The check goes through `resumable_fit`, which
applies the degenerate rule exactly as the SolverBuilder, the Validator and the
blocker analysis do. The three must agree or the answer states a change the
solver would ignore.

### The hard rule, enforced by shape

Each lever removes the bound that binds. Whether the solver would then place the
operation there needs a re-solve, which R-AI4 forbids. So **every answer names
the NEXT bound**, and where the binding family is not chunk-fit that next bound
is recomputed through the tail of the ladder rather than assumed to be the
runner-up — relaxing precedence can expose a chunk-fit the runner-up never
mentioned.

### Three things it refuses to price, all named

* **B7/B8 changeover** — 4B.14's precedent: the setup at an earlier position
  depends on what would then precede it, which is a different schedule.
* **The objective**, on a `chose` verdict. There the honest counterfactual is
  "nothing has to change", and inventing a barrier to have something to offer
  would be the same over-claim `why-here` was built to end, wearing a helpful
  face.
* **A declared closure** in the way. Lifting a maintenance day would plainly
  move the operation, so leaving it out would be a hole in the disjunction — but
  saying what a machine's open hours would be on a day the calendar declares
  shut is an invention, not a reading.

### The B1 lever is computed, not restated

"431 contiguous minutes free on an eligible machine" is the brief's *condition*.
The route resolves capability eligibility and scans each other lane **from the
same upstream floor** (release, precedence, frozen, pin — the bounds a different
machine is still subject to). Scanning from the beginning of the alternative's
calendar would report open time before the order was released: true about the
machine, false about the operation. On the pinned board PAINT-01 is the only
eligible lane, and saying so is stronger than offering a door already shut.

## Item 2 — the opener

`briefing` widens from the 7am triage to the whole-board read.
`src/mre/modules/board_opener.py` builds every item the document supports,
**ranked by consequence**, each line carrying its own number and a pointer to
the question that opens it up. Entirely contracted testimony; no synthesis on
the primary path.

Measured on a real monolithic run:

```
40 orders on 6 machines over 2026-01-05 to 2026-04-16. 3 things worth your
attention, worst first:

1. The cost optimum is NOT proved — the solver stopped with a gap of 56.9%
   still open.
     Against a ledger of 42,895.47, that bound leaves up to 24,414.97 on the
     table — an upper limit on what a cheaper schedule could save, not a
     saving anyone has found.
     -> Ask "is this schedule optimal?" …

2. 13 order(s) finish late in this window, costing 20,701.25.
     ORD-000014 — 6d 15h late …
     -> Ask "why are so many orders late?" …

3. 2 data-quality finding(s) stand against this submission.
     2 of them were PROCEEDED PAST — the plan was built anyway, with the
     defect disclosed rather than fixed.
     -> Ask "what should I fix first?" …

Not covered by this read:
  · work beyond the planning horizon — this is a monolithic run …
  · whether the coming weeks fit — the coarse zone did not run on this solve …
```

and on the pinned rolling world, whose worries are 2 at-risk orders, the Jan 14
maintenance day across 9 machines, 14 orders beyond the horizon and an
undeclared derate — over two CLEAN items: nothing late, cost optimum proved.

### The ranking rule is stated, because a ranking nobody can check is an opinion

* **Band 1 — money at stake**, and its two members are comparable because both
  are currency: controllable tardiness (R-PD1 clause (4): never the floor, which
  no placement can recover — ranking on the fused number would put a board at
  the top of the list for work that was already late when it arrived) and the
  unproved gap priced against the ledger.
* **Band 2 — work that will slip**: at-risk, unplaced, closures. None has a
  price without a re-solve, so they rank by count.
* **Band 3 — structure**: concentration, the certificate, an undeclared margin.
* **Band 4 — clean**: reassurance, reported last.

Within a band the priced item leads — not because it matters more in principle,
but because it is the only one whose size is known.

### Three things it will not do

* **It will not stay silent on a good board.** A proved optimum and an empty
  late list are REPORTED as reassurance, so "three things, and none of them are
  on fire" is a reachable answer rather than a silence a planner must interpret.
* **It will not call a busy machine a concentration without eligibility.** At
  88% beside two idle ones is a finding only if those machines could have taken
  the work; otherwise it is what a specialised cell looks like.
* **It will not drop a category quietly.** A monolithic run says it has no tray;
  a solve without the coarse zone says the coming weeks were not checked; an
  answer without a document says it is reading the evidence store alone.

## Carried, not fixed

* **The opener's certificate item cannot state the GRADE.** It is a submission
  fact the API joins on `/meta`; the schedule document does not carry it. The
  one word a stranger recognizes ("ACCEPTED") is the one this item cannot say.
  `RECON_GATEHOUSE.txt` Q1 names the same seam from the other side.
* **Concentration did not fire on either measured board.** Demo density runs far
  below the 85% threshold, so the item is unexercised live and proven only by
  unit test — the same limit §5a.11 recorded for the coarse zone.
* **A planner-named DAY is not parsed.** "Can this move to Monday" is answered
  about the target the route computes, naming the weekday and date it tested.
  Resolving "Monday" to one of five Mondays is the class §5a.45 measured.
* **Neither route was measured against a live parse.** Both were exercised
  through the dispatch by route id and against two real boards; whether the
  model actually reaches them from a planner's phrasing is the exam sweep's job,
  and the sweep still needs `ANTHROPIC_API_KEY` (§5a.7).
