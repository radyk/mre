THE CAUSE IS NOT IN M6. IT IS IN THE REPORTER, AND IT IS STRUCTURAL.

    Reporter.record_event         hardcodes subjects=[]   (reporter.py:302)
    Reporter.register_input       hardcodes subjects=[]   (:167)
    Reporter.register_output      hardcodes subjects=[]   (:332)
    Reporter.record_metric        defaults  subjects=[]   (:261)
    record_decision / record_finding require subjects, but a caller may pass []
      for a genuine run-level fact, and solve_runner does.

So EVERY Event and EVERY Artifact the system has ever emitted is subject-less
by construction. save() persisted three DERIVED indices; load() rebuilt
_all_evidence from entity_records alone. solve_complete was not a special case.
It was the one whose consumer was loud enough to notice.

THE SHARPEST CASUALTY IS THE FINDING, BECAUSE IT DID NOT MERELY GO MISSING --
IT MADE ONE INDEX CONTRADICT ITSELF. A subject-less finding was persisted in
finding_index and absent from _all_evidence, and those two structures back two
different queries:

    ONE LOADED INDEX, TWO ANSWERS
      finding_occurrences('SOLVER_NONOPTIMAL')  -> 1
      all_findings() containing it              -> 0

Ten all_findings() call sites in explainer.py plus evidence_tools.py:492 read
the side that says zero. planner_language.py:75 maps that code to "was
scheduled before the solver could prove the best plan" -- a phrase unreachable
from a loaded index, independently of the cost proof.

WHY THIS DECIDED THE RULING'S SHAPE. The brief's fix (i) as written -- "persist
run-level records" -- would have landed as "also persist the solve_complete
Event". That fixes the specimen and leaves the input manifest, the C0-C3
evidence and the finding contradiction in place: exactly the "makes the seam
look closed" failure the brief warned about. The session stopped here and
reported before implementing, and the ruling was taken in a different shape.

======================================================================
THE RULING (verbatim in docs/04, 2026-07-30)
======================================================================

(ii) -- dropping the load-if-exists preference at api/app.py:1482 -- is
REJECTED on the brief's own reasoning: it leaves a persisted artifact that
silently is not a faithful copy of what it was saved from, and the next
consumer to load it inherits the hole untold.

(i) is TAKEN, at the ROOT rather than per class. _all_evidence becomes the
PRIMARY persisted structure; entity_records and finding_index are DERIVED on
load through _index_record, the same code path build() uses.

    save()   {"schema_version": 2, "all_evidence": [...], "run_registry": {...}}
    load()   _all_evidence read directly; the two indices derived from it

run_registry is still written because it is NOT derivable from evidence
records -- it is folded from run_context_open/close lines, which build()
consumes and never places in _all_evidence.

It is also SMALLER, because schema 1 stored each record once per subject
entity: 192,767 -> 181,644 bytes on the specimen, 0.94x.

COMPATIBILITY. An old index still loads; nothing on disk is invalidated. A
schema-1 file is detected by the absent schema_version, its subject-bearing
records are recovered as before, and subject-less findings are additionally
recovered out of finding_index so the self-contradiction above is repaired even
unmigrated. What cannot be recovered is DECLARED: EvidenceIndex.incomplete
names the CLASSES the file cannot vouch for -- classes not counts, because a v1
file gives no way to know how many were dropped, only which shapes could not
have survived.

FORWARD compatibility is NOT provided, and is named here rather than discovered
later: a schema-2 file read by pre-4B.18 code yields an EMPTY index, because
that code reads entity_records and the key is gone. That failure is loud
(nothing answers at all) rather than subtly wrong, and this repo ships one
commit per image.

THE INVARIANT:

    A PERSISTED EVIDENCE INDEX IS A FAITHFUL RECONSTRUCTION OF THE INDEX IT WAS
    SAVED FROM. Any record class the builder places in _all_evidence is
    recoverable after a round trip, or the load reports the index as INCOMPLETE
    and names what is missing. Silence is forbidden: an answer surface may not
    be unable to distinguish "this never happened" from "this was not
    persisted".

CostProof gains a FOURTH state, unreadable, taking priority over the other
three. no_solve and unproved are both False under it, so no surface can make a
claim about the PLANT out of a fact about our STORAGE. Each of the three
surfaces gets an authored unreadable branch and NONE may stay silent --
including the money rider, where silence is not neutral: on that surface
silence MEANS proved, because proved is the only other state that says nothing.

WHAT WAS TEMPTING AND LEFT
======================================================================

A1 (door labels asserting board facts), A2 (the 8-of-15 machine list), A3 (the
merged-span fourth seam) and A5 (the evidence chain) are untouched, as is the
dark-evidence premise-correction false positive and CLAUDE.md compression.

Two things this session's own diagnosis surfaced and did not chase:

  * THE REPORTER'S SUBJECT-LESS VERBS ARE NOT CHANGED. record_event emitting
    subjects=[] is CORRECT for a run-level fact. The defect was never that
    those records lack subjects; it was that persistence was built on the
    assumption that none does. Giving Events synthetic subjects would have
    fixed this symptom by corrupting the subject vocabulary, which is worse.

  * A SCHEMA-2 FILE THAT IS LOSSY FOR SOME FUTURE REASON IS NOT
    SELF-DETECTING. incomplete covers schema 1 only -- proven by the negative
    control, where the stubbed save produced a lossy file that still declared
    schema 2 and reported incomplete=(). The round-trip guard is what stands in
    that gap, which is the honest place for it: a file cannot audit itself, and
    a test can.

  * THE SEVEN SCHEMA-1 INDEXES IN _data/runs/ ARE DELIBERATELY NOT MIGRATED.
    They are the live specimens for the incomplete path, and a re-solve
    migrates any of them for free. Migrating them would have destroyed the only
    unmigrated artifacts this repo has, one session after building the code
    that handles them.
