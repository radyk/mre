----------------------------------------

runs three chunks and completes 2026-01-12 15:37; 19:00 on the 8th is its first

FIRST chunk only.

4B.13 fixed this exact class in assemble_rolling_document and confirmed the

3. WHAT WAS BUILT
======================================================================

ITEM 0  The explainer's row model reads WHOLE operations. `end` is the last run
        window's end; `chunks`, `run_min`, `span_min`, `splittable` and
        `min_chunk` ride with every row.

ITEM 1  causal_sufficiency.py — a deterministic floor. When an answer explains a
        quantity by citing a cause, the cited cause must ACCOUNT for it. For the
        "held until T, so it took the next opening" shape that is an arithmetic
        identity: the explained start must equal the first open window on that
        resource at or after T. Computed at the assembler (so the sentence is
        true when composed) and enforced at the one delivery seam both renderers
        share (so a reword cannot put the claim back).

        The vacuity tripwire (4B.5 CU3) cannot catch this and neither check
        subsumes the other. The specimen names an order, a machine AND a
        timestamp; it passes vacuity cleanly, and would pass with the timestamp
        off by a year.

ITEM 2  blocker_analysis.py — an earliest-feasible-start per docs/05 family,
        computed independently from the persisted document: release A4,
        precedence A1/A2, frozen R-F1, pin A7/F1, resource B1, calendar C1/C2,
        chunk-fit C3. BINDING is the earliest family attaining the maximum; the
        tie rule is load-bearing (precedence and chunk-fit landing together
        means precedence pushed it). RUNNER-UP is the previous pusher.

        COULDN'T versus CHOSE-NOT-TO is a first-class verdict, not a footnote.
        A third verdict, UNDETERMINED, covers the case where the actual start
        precedes every computed bound: that is a contradiction in our own
        reading, and R-AI3(1) says say nothing rather than pick a branch.

        `why-here` joins the closed vocabulary — a vocabulary-class change paid
        in full: Intent, INTENT_MEANINGS (written as a PAIR with start-reason so
        the model learns the boundary), ROUTE_TAXONOMY, ROUTE_OFFERS, the
        assembler, authored copy, parse prompt v11.

ITEM 3  ContestedClaim (lateness / timing / other). The parse REPORTS which
        claim is disputed; the dispatch decides. A `timing` contest is answered
        by the blocker analysis on the planner's own terms, and where the
        planner is RIGHT the answer says so first. Carried on `why-here` too,
        because a challenge usually names the right route by itself and would
        otherwise lose the fact that someone pushed back.

        predicate_coverage went from one entry to three: `disagreement` and
        `temporal_alternative`, both measured.

ITEM 4  Contract 1.11 -> 1.12: AssignmentBlock.splittable + min_chunk_min, both
        Optional. The job card carries start/finish, RUN TIME and ELAPSED SPAN
        as separate labelled rows (elapsed only when it exceeds the run), chunk
        count, the splitting rule, due and slack.

ITEM 5  (a) A transport failure is a connection notice with a retry, not a chat
        turn in the testimony register. (b) The temporal-alternative predicate
        reaches the blocker analysis. (c) `cited_refs.alternatives` is its own

4. FOUND AND REPORTED, NOT FIXED
======================================================================

(a) A `chose` VERDICT ON A SPLITTABLE OPERATION IS A LOWER BOUND. Setup is a
    separate phase with its own R-C3 interruptibility class, and the fit scan
    treats an operation's working minutes as one divisible quantity. So the copy
    claims exactly what is computed — "there was open, unheld time on the machine
    from T" — and never "the solver could have placed it there". The wording is
    the mitigation; the limit is real and stated in the module docstring.

(b) THE RUNNER-UP CAN BE A STALE TRUE FACT. On ORD-000013's op10 the previous
    pusher is CUT-01's calendar opening on Jan 5, eight days before the start
    being explained. The renderer suppresses it when the binding family's
    near-miss window is more recent. That is a heuristic about relevance, not a
    proof, and a differently-shaped world could still surface a true sentence
    that adds nothing.

(c) `start-reason` WAS NOT RETIRED. It still answers "why does it start when it
    does" and "why so early", and it now honours the selected operation and
    carries the sufficiency fact. Whether the two routes should merge is a
    vocabulary question this session did not rule on.

(d) CLAUDE.md IS 45k AGAINST ITS 40k PHASE-EXIT CEILING (43k before this
    session). Three superseded blocks were compressed; the file still grew.

THE TEST THAT WAS WRONG IN A USEFUL WAY. Writing test_causal_sufficiency.py,
the "a sufficient cause is left alone" case was drafted with the CORRECTED
timestamp (ORD-000011's real end, 2026-01-12 15:37) and it went red. The code

  FIXING THE TIMESTAMP DOES NOT MAKE THE SENTENCE TRUE. CUT-01 frees mid-shift
  on Monday; the operation starts Tuesday morning. "So it took the next opening"
  is still false, because the real cause is chunk-fit.

So the session's two fixes are genuinely independent. The chunk repair makes the
cited NUMBER true. Only the blocker analysis makes the CAUSE right. Only the
sufficiency check can tell that a corrected sentence is still over-claiming.
That case is now pinned as its own test.

found the first-chunk-only read in the document assembler and on the board, and
stopped there. The third consumer produced a wrong number in PROSE, where
nothing draws it, so nothing looked wrong.
