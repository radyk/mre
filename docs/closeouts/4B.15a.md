2.2 THE ZERO-TOOL-CALL GUARD  (`src/mre/modules/ungrounded_guard.py`)

  THE SPECIMEN (4B.15 section 6(b)): Opus, asked which machine carries the most
  work, named three machines that DO NOT EXIST in this plant, with ZERO tool
  calls. Claim verification did its job -- every sentence was labelled
  unsupported -- and the answer SHIPPED, because the tier's contract is to LABEL
  what it grounds, not to withhold what it cannot.

  A synthesis answer that read nothing and still names this plant's entities did
  not reason from evidence; it recalled a plausible shape. It now does not ship.
  Three conditions, all deterministic, no model judgment anywhere:

    (1) the answer came from the SYNTHESIS tier,
    (2) ZERO tool calls AND no cited record that RESOLVES against the evidence
        index, and
    (3) a delivered claim names something specific to THIS WORLD -- an entity
        identifier, money, an ISO date, a clock time -- THAT THE PLANNER DID NOT
        PUT THERE THEMSELVES.

  CLAUSE (3) IS WHAT MAKES IT SAFE. A token the planner typed is not the tier's
  invention: an answer echoing "ORD-000013" back at the person who asked about
  ORD-000013 fabricated nothing. Only tokens the tier INTRODUCED count -- which
  is exactly what the Opus specimen looks like, and exactly what an honest
  no-tools answer does not do. A bare integer is deliberately not a world token
  ("two ways to read that" is prose, not a claim about the plan).

  CLAUSE (2)'s second half is what makes it dodge-resistant. A model that
  invents record ids alongside its machines gains nothing: the assembler resolves
  cited ids against the real index and drops the rest, so a fabricated citation
  is an empty list, not a free pass.

  Attached at the ONE delivery seam BOTH renderers share, like the cost-proof,
  sufficiency and coverage riders -- and it is the only one there that WITHHOLDS
  rather than qualifies, because the defect is not an under-stated
  qualification, it is an answer with nothing behind it. It fails OPEN in every
  direction: an odd bundle shape, a missing count, an exception, all deliver the
  answer untouched.

  THE NEGATIVE CONTROL, which the errand required and which is the test that
  matters most: a synthesis answer that legitimately needs no tools STILL SHIPS.
  The bench's own floor question is the control -- "what will the weather be on
  delivery day" has no answer in any evidence store, and the right response reads
  nothing and says so. `TestNegativeControl` pins four of them (the weather
  floor, a general statement about the product's scope, a bare count, and the
  no-claims honest floor). Without it the guard is a mute button on the second
  tier, and the honest floor is the first thing a mute button eats.

  `tests/test_ungrounded_guard.py`, 16 tests.

5. WHAT IS OWED, REPORTED AND NOT FIXED
================================================================================

(a) THE P90 IS A DEMO RISK AND THE FIX IS NOT A MODEL. Section 1: the
    second tier's tail is 6-9x its median on EVERY tier, including Haiku. That
    is the multi-step tool loop, not the model class. If interactive feel
    becomes the binding concern the lever is streaming the first beat or running
    the loop in the background, not a cheaper synthesizer -- a cheaper model
    runs the same steps faster, it does not run fewer.

(b) THE BANK CANNOT RESOLVE THE QUALITY DIFFERENCE. Two runs, unstable ranking
    on every quality column (section 1). A tier decision that wants to rest on
    correctness needs a bigger bank or repeated runs; today's rests on cost,
    facts-reached in both runs, and Daryn's call. Not a defect -- a limit that
    must travel with the number.

(c) A CORPUS-GROUNDED CLAIM CANNOT CARRY A [record:] CITATION. Q1's four claims
    are all interpretive because corpus and catalog tools return spec text, not
    evidence records, so `claim_verifier` has nothing to re-fetch. The answer is
    correct and the label is honest, but the surface makes a documentation-
    grounded answer look weaker than an occupancy-grounded one. The fix is a
    citation kind for spec passages, which is a contract change.

(d) THE GUARD IS SCOPED TO THE SYNTHESIS SUBJECT TYPE. `prove_it` (the grounding
    pass) is a second model surface at the same seam and is not covered. It
    re-runs grounding on one existing claim, so it has a different failure mode;
    covering it was not measured and is not assumed.

(e) 4B.15's OWN CARRY-FORWARDS ARE UNTOUCHED, as the errand scoped: the
    synthesis toolbox still cannot read a declared field (the third tool wrapping
    `attribute_lookup`), the deafness rider still fires when the one answer is
